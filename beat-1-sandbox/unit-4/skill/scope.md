# Scope: where your pull request lives, and the rules of the room

## Where your pull request lives

Only pull requests against the course's Path Review repository are in scope this week:

- Repo: `codepath/pathreview-ai301-fa26-s1`

Your pull request must implement the plan you posted in week 3 (or the house plan the instructor routed you to), on the issue that plan belongs to. Do not grade PR packages for any other repository. Eval runs ignore this file.

## Path Review house rules

- **PR from your own fork's branch.** Open the pull request from the `fix/<issue-number>-<slug>` branch on your fork against the semester repository's default branch. Do not push directly to the shared repository.
- **One PR per issue, per student.** Deliver one bounded change from the posted plan. Follow-up work belongs in a new issue rather than an expanding PR.
- **Use the complete PR template.** Give every section real content, including required disclosure. Check only statements supported by evidence.
- **A classmate's PR does not block yours.** Multiple students may fix the same shared issue; open your own PR from your own plan and branch.
- **Credit attaches to opening the PR.** Readiness does not depend on whether staff later reviews, merges, or closes it.
