# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| claim-specific-intent | The candidate claim comment read against the issue title/body and thread highlights | The claim identifies this issue through a concrete symptom, trigger, component, or investigation target and states a plausible next action. It does not pass if it is interchangeable assign-me/"same here" text, promises a fix or deadline, or claims certainty not yet supported. | required |
| environment-fit | The repro report's environment record read against the issue's stated platform, versions, configuration, and repo-facts requirements | The report identifies the OS/platform and the tool/runtime version plus any configuration or dependency that materially affects the trigger. The setup matches the issue's target, or every material difference is named and its effect or limitation is kept explicit. | required |
| steps-rerunnable | The repro report's starting state, commands/configuration/input, and ordered actions read against the issue's trigger | A stranger can recreate the tested state and exercise the relevant trigger using information in the comment or a public artifact it links. No essential step, input, configuration, credential, or private file is unavailable. A control run is useful when needed to distinguish the trigger, but is not required when the shown result is otherwise unambiguous. | required |
| behavior-directly-shown | Output excerpts, logs, screenshots, measurements, or other artifacts in the repro report read against the exact behavior and expected result described by the issue | The artifacts directly distinguish the issue's reported behavior from normal behavior or an adjacent failure. For a cannot-reproduce report, they instead show a faithful attempt completing without the reported behavior. Assertions, version banners, setup-only output, and artifacts from a changed trigger do not pass. | required |
| conclusion-calibrated | The claim comment and the repro report's expected/actual statements, interpretation, and any cause claim read against the steps, environment, and artifacts | The conclusion says no more than the evidence supports: reproduced, could not reproduce, or inconclusive is stated consistently with the artifact. Material deviations are acknowledged, expected and observed behavior are not reversed, and any root-cause claim is either demonstrated or clearly framed as a hypothesis. | required |
| repo-conventions | The repo-facts contribution policy and bug-report requirements read against both candidate comments; in live mode also the repository's current CONTRIBUTING, AI-policy, issue-template, and thread instructions | The comments satisfy every stated requirement that applies to issue comments, including an AI-assistance disclosure when the repository requires one. Do not invent a disclosure requirement when policy is silent or merely permits AI use. | required |

## Verdict rule

Accept only when every applicable required check passes. Reject when any applicable required check fails or is unclear. Preferred checks, if added later, never change the verdict. In a claim-only live run, `environment-fit`, `steps-rerunnable`, `behavior-directly-shown`, and `conclusion-calibrated` are not yet applicable: report them as `unclear` with the required claim-only evidence text, omit them from the verdict calculation, and decide the claim using `claim-specific-intent` and the claim-applicable portion of `repo-conventions`.
