# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | The accepted plan's outcome, scope, exclusions, named files, approach, test or documentation deliverables, known limits, and `## Deviations`, read against the complete diff, commit list, title, and description | Every meaningful diff change is authorized by the plan or a specific recorded deviation, and every material planned deliverable is present unless the plan or deviation explicitly defers it. Every material description claim matches the diff and the authorized boundary. Hidden extra work, silently omitted work, or a false fidelity claim fails. A known limit or smaller outcome explicitly authorized in the accepted plan or a recorded deviation and restated accurately in the description passes; do not require the PR to solve work that its accepted boundary deliberately defers. | required |
| test-evidence-decisive | The plan context's reproduction and test plan, issue trigger and controls, candidate test-evidence section, new or changed tests in the diff, and repository checks required by repo facts | The evidence establishes the issue-defining changed path with a concrete broken-versus-fixed observation. Each separately promised acceptance target with a distinct trigger or expected behavior has an explicit result. Repeated applications of the same mechanism across analogous call sites do not require separate reproductions unless the plan promises separate cases; representative regression coverage plus the specific broader-suite result may establish them. Named controls and applicable repository checks have specific reported outcomes, but supporting results need not include full transcripts. Generic assurances, a suite name without a result, evidence only from an unchanged control, or omission of a separately promised path fails. A reported check failure may pass only when its result is shown, the description discloses it, and the evidence establishes that it is unrelated to the changed behavior; failure on the changed path fails. | required |
| diff-reviewable | The complete unified diff and commit list, with each hunk classified as planned implementation, planned test/documentation, necessary mechanical support, or debris | The intended change and regression coverage are directly reviewable, and no debug output, commented-out experiment, dead helper, stale TODO, unrelated refactor, drive-by edit, duplicated code, or formatting/import churn materially obscures or enlarges the change. Commit wording alone does not fail an otherwise clean diff, but commits and hunks together must let a reviewer isolate the intended work. | required |
| repository-standards | The repo-facts block or, live, the PR template, contribution guide, policy files, and explicit issue-thread directions, read against the candidate title, description, checklist claims, disclosures, diff, and test evidence | Every stated mandatory submission requirement is satisfied with truthful content: required template sections and issue linkage are present; required checklists reflect the evidence; required tests, changelog or release-note files appear when the repository demands them; explicit maintainer directions are engaged; and every required AI-use disclosure names the tool and extent. Do not invent requirements when the repository states none. | required |

## Verdict rule

Grade every row `pass`, `fail`, or `unclear`. Accept only when every required check passes. Reject when any required check fails or is unclear. `Unclear` means the package lacks enough verifiable evidence to apply the pass condition and counts as failure; never fill the gap with assumptions. Preferred checks, if added later, may appear in the summary but never change the binary verdict.
